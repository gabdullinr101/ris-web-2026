# Известные дефекты и ограничения

Найдены при сквозной проверке (ЛР12). Приоритет - как в ЛР13: 1 - не запускается, 2 - ломается критерий, 3 - нет сохранения, 4 - неверный код, 5 - права, 6 - документация, 7 - косметика.

## Открытые

## D-01. Зал вводится номером, а не выбирается из списка
- Приоритет: 7 (критерии выполняются).
- Шаги / ожидали / получили: «Создать» → поле «Номер зала (hallId)». В сценарии ЛР1 администратор «выбирает зал», ожидали выпадающий список с названиями; получили числовое поле.
- Обход: номера залов есть в README (1 - тренажёрный, 2 - единоборств, 3 - групповых программ). Несуществующий номер сервер отклоняет: 400 «Зал с таким номером не найден», запись не создаётся.
- Статус: открыт.

## D-02. Учебный mock умеет только список и создание
- Приоритет: 6.
- Шаги / ожидали / получили: в `.env` поставить `VITE_USE_MOCK=true`. Вход, назначение и смена статуса всё равно идут на сервер; если сервер не запущен - «Нет связи с сервером».
- Обход: рабочий режим - `VITE_USE_MOCK=false` (по умолчанию в `.env.example`). Mock оставлен как учебный артефакт ЛР6.
- Статус: открыт, исправлять не планируется.

## D-03. Миграция не применяется поверх таблиц из скриптов ЛР9
- Приоритет: 1, если читать README невнимательно.
- Шаги / ожидали / получили: создать базу `fitness_bookings` скриптами `db/schema.sql` и `db/seed.sql`, затем `dotnet ef database update`. Ожидали - миграция пройдёт; получили `42P07: relation "halls" already exists`.
- Обход: в README шаг 3 «Подготовки» - удалить базу перед первой миграцией; для SQL-скриптов в README отдельная база `fitness_sql`.
- Статус: открыт, закрыт документацией.

## D-04. Нет страниц и фильтров в списке
- Приоритет: 7.
- Шаги / ожидали / получили: НФТ-2 «100 записей открываются быстрее 2 секунд» не замерялось; список выводится целиком, без страниц и фильтра по статусу.
- Статус: открыт, на ВКР.

## D-05. Управляющий не видит сводку по статусам на экране
- Приоритет: 7.
- Шаги / ожидали / получили: в ЛР1 управляющий «понимает, что взято в работу, а что отменено». На экране - общий список со статусами, отдельной сводки «сколько в каждом статусе» нет; она есть только запросом `GROUP BY status` в `db/queries.sql`.
- Статус: открыт, на ВКР (аналитика за границей семестра).

## Закрытые

## D-06. Экран входа мигал формой после F5
- Приоритет: 7.
- Шаги / ожидали / получили: войти, открыть `/login`, нажать F5. Ожидали сразу «Вы вошли как …»; получили на долю секунды форму входа, пока клиент спрашивал `GET /api/auth/me`.
- Причина и исправление: экран не знал, что проверка входа ещё идёт. В `frontend/src/authStore.js` добавлен флаг `authChecked`, `Login.vue` до ответа сервера показывает «Проверяем вход…».
- Повторная проверка: F5 на `/login` после входа - формы нет, сразу «Вы вошли как Анна Ковалёва (администратор)»; без входа - форма, курсор в поле «Логин».
- Статус: закрыт.

## D-07. Разъезжалась граница строки в колонке «Действия»
- Приоритет: 7.
- Шаги / ожидали / получили: войти тренером с записью - линия под ячейкой «Действия» короче и выше, чем у остальных ячеек строки.
- Причина и исправление: у самой ячейки `<td>` стоял `display: flex`, и она переставала быть ячейкой таблицы. Кнопки обёрнуты в `<div class="actions">`.
- Повторная проверка: строка таблицы ровная, кнопки по-прежнему переносятся.
- Статус: закрыт.
