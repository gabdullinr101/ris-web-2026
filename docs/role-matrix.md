Роли из ЛР1 (docs/lab-01-requirements.md). Права проверяет сервер: `[Authorize]` на контроллере даёт 401 без входа, `BookingService` даёт 403 по роли и по владельцу записи. Спрятанная кнопка в Vue - только подсказка.

## Роль × действие

| Действие | Администратор | Тренер | Управляющий | Гость (не вошёл) |
|----------|---------------|--------|-------------|------------------|
| `POST /api/bookings` создать | да → 201 | нет → 403 | нет → 403 | нет → 401 |
| `PATCH …/assignee` назначить | да, запись в статусе New → 200; в работе → 409 | нет → 403 | да, New и InProgress → 200 | нет → 401 |
| `PATCH …/status` своей записи | нет → 403 | да → 200 (если переход допустим, иначе 409) | нет → 403 | нет → 401 |
| `PATCH …/status` чужой записи | нет → 403 | нет → 403 | нет → 403 | нет → 401 |
| `PATCH …/status` записи без тренера | нет → 403 | нет → 409 | нет → 403 | нет → 401 |
| `GET /api/bookings` список | все записи | только свои | все записи | нет → 401 |
| `GET /api/bookings/{id}` | да | своя → 200, чужая → 403 | да | нет → 401 |
| `GET /api/users/trainers` | да | нет → 403 | да | нет → 401 |

Кто создаёт, тот не меняет статус (ЛР1): администратор и управляющий статус не двигают.

## Где в коде

| Проверка | Файл |
|----------|------|
| без входа - 401 | `backend/Controllers/BookingsController.cs` - атрибут `[Authorize]`; `backend/Auth/AuthSetup.cs` - вместо перенаправления на страницу входа код 401 |
| роль - 403 | `backend/Services/BookingService.cs` - `Create`, `Assign`, `ChangeStatus` |
| чужая запись - 403 | `backend/Services/BookingService.cs` - `ChangeStatus`: `booking.AssigneeUserId != user.Id`; `GetById` и `GetAll` для тренера |
| кто вошёл | `backend/Auth/CurrentUser.cs` - id и роль из cookie, не из тела запроса |
