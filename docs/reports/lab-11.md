# ЛР11. Вход и права

Появились «кто ты» и «можно ли тебе». Без входа сервер ничего не отдаёт и не создаёт (401). Вошедший без нужной роли и тренер с чужой записью получают отказ (403). Пароли в базе - hash библиотеки. Описание со `<script>` на экране Vue - обычный текст.

## Способ входа - cookie

Выбран вход через cookie (не JWT). `POST /api/auth/login` проверяет логин и пароль и ставит cookie `fitness_auth`. Браузер сам присылает её со следующими запросами, клиент на `:5173` просит об этом через `fetch(..., { credentials: 'include' })`.

- cookie `HttpOnly` - JavaScript страницы её не видит;
- `SameSite=Lax` - Vue на `localhost:5173` и API на `localhost:5000` считаются одним сайтом;
- у API нет страницы входа, поэтому вместо перенаправления сервер отвечает кодами: не вошёл - 401, нельзя - 403 (`backend/Auth/AuthSetup.cs`);
- CORS разрешает читать ответы только `http://localhost:5173` и с cookie (`AllowCredentials`); чужой origin разрешения не получает - проверено preflight-запросом.

Новые адреса: `POST /api/auth/login`, `POST /api/auth/logout`, `GET /api/auth/me`, `GET /api/users/trainers`. Заголовок `X-User-Id` из ЛР8 больше не используется: кто выполняет запрос, сервер берёт из cookie (`backend/Auth/CurrentUser.cs`).

## Пароли - hash

Hash посчитан `PasswordHasher<User>` из ASP.NET Identity: формат v3 - PBKDF2-HMAC-SHA512, случайная соль, 100 000 итераций. В базу hash попадает миграцией `AddUserPasswordHashes`; при входе пароль сверяется через `VerifyHashedPassword`, открытого пароля в базе нет.

```text
  login   |  role   |                                    password_hash
----------+---------+--------------------------------------------------------------------------------------
 admin    | Admin   | AQAAAAIAAYagAAAAEAw/EGtrNeEt1C9Uo7lWtpUMvIsHVMeTfWUsHnApVx7Mu1EXYmWv0scWDnyEmL4hvA==
 trainer  | Trainer | AQAAAAIAAYagAAAAEDcgI/aryuvEd4XMzMXz53H0v9Duh1xsLmHnVYGb9eYwM7lXFkh3gzPnt3L7vaLy7Q==
 trainer2 | Trainer | AQAAAAIAAYagAAAAEO39nFcWqFHojE5/9bd3ciqh887qf639LgbPU2WF+YEnHDl+0XcIg4oCKgDRy6FRQw==
 manager  | Manager | AQAAAAIAAYagAAAAEDiJbFxktscOqHrVrk/CWkxC0w2J/l0JxsNBRKdueSBOAMlU6Cjs7mItGbmS61stkQ==
```

Пароль у всех одинаковый, а hash разные - это работает соль. Строка hash записана буквами Base64, но это запись *результата* хэширования, а не самого пароля: раскодировав её, получишь соль и 32 байта PBKDF2, пароль из них не восстановить. Base64 самого пароля (`Rml0bmVzczIwMjYh`) раскодируется обратно за секунду - поэтому так хранить нельзя.

## Права

Полная таблица - `docs/role-matrix.md`. Кратко:

- без входа - 401 на все адреса записей (`[Authorize]` на контроллере);
- создаёт только администратор, иначе 403;
- назначает администратор (запись New) и управляющий; тренер - 403;
- статус меняет только назначенный тренер своей записи; чужая запись - 403; администратор и управляющий - 403;
- тренер видит в списке только свои записи, чужую по id - 403.

Где проверяется чужой id: `BookingService.ChangeStatus` сравнивает `booking.AssigneeUserId` с `user.Id` текущего пользователя из cookie. Подставить в адрес чужой id не поможет.

## Экран входа

`/login` (`frontend/src/pages/Login.vue`) отправляет логин и пароль в `POST /api/auth/login`. После успеха - переход на список, в шапке имя и роль. После F5 вход сохраняется: клиент спрашивает `GET /api/auth/me`, cookie живёт 8 часов. Вход всегда идёт на настоящий сервер, даже при `VITE_USE_MOCK=true`.

Запросы на порт 5000 во вкладке Network при прогоне в браузере (`VITE_USE_MOCK=false`):

```text
GET  /api/auth/me     401   ← открыли список без входа
GET  /api/bookings    401   ← на экране «Войдите в систему»
POST /api/auth/login  401   ← неверный пароль, «Неверный логин или пароль»
POST /api/auth/login  200   ← вход admin
GET  /api/bookings    200
POST /api/bookings    201   ← создание с описанием <script>alert(1)</script>
GET  /api/bookings    200
POST /api/auth/logout 200
POST /api/auth/login  200   ← вход trainer, ссылки «Создать» в шапке нет
POST /api/bookings    403   ← тренер открыл /new вручную и отправил форму: «Создавать записи может только администратор»
```

Ссылка «Создать» спрятана для тренера только как подсказка: запрос из той же формы сервер всё равно отклонил с 403.
